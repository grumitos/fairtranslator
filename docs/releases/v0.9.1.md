# FairTranslator v0.9.1

Patch release focused on long-running Codex QA translation campaigns and Windows
run hygiene.

## Highlights

- Hardened `qa_translate_provider` against malformed provider responses by
  retrying schema/entry-shape errors and isolating problematic entries instead
  of failing an entire long campaign immediately.
- Updated Codex CLI execution to use the current `model_reasoning_effort`
  config key and bounded `codex exec` calls with a five-minute timeout.
- Made planner cache data serializable enough to reuse chunk plans across
  resumes while filtering entries that were already completed.
- Stabilized planner cache invalidation so translation progress alone does not
  invalidate a reusable plan, while source text/context changes still do.
- Added a Windows run-hygiene script for `D:\FairTranslatorRuns` with dry-run
  reporting, explicit keep/remove options, and safe root-bound deletion.
- Release workflow now publishes tag builds instead of leaving them as drafts.

## Validation Snapshot

The release gate for this tag should include:

- `cargo fmt --check --manifest-path src-tauri\Cargo.toml`
- `cargo test --manifest-path src-tauri\Cargo.toml --bin qa_translate_provider -- --nocapture`
- `cargo test --manifest-path src-tauri\Cargo.toml translation_orchestrator -- --nocapture`
- `cargo test --manifest-path src-tauri\Cargo.toml codex -- --nocapture`
- `cargo test --manifest-path src-tauri\Cargo.toml --no-fail-fast`
- `npm run build`
- `npm run test:run`
- `npm audit --audit-level=high`
- `npm run tauri -- build`

Windows Rust/Tauri validation may need to run from a Visual Studio developer
environment so `link.exe` is available.

## Known Limits

- The QA runner still depends on a locally authenticated Codex CLI for Codex
  provider runs.
- `D:\FairTranslatorRuns` cleanup is intentionally conservative by default and
  performs a dry run unless `-Apply` is passed.
- In-game visual QA is still required for text overflow in exported games.
